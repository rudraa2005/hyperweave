# Data and artifact handoff

The local test suite uses small fixtures. The official NF-v2 CSVs below are now
present locally as ignored data files. They were found in UQ BagIt folders under
`hyperweave/data/raw/` and hard-linked into the canonical `data/raw/` paths.
They are not committed to this repository. The real endpoint-group study and
its artifacts are recorded in [Phase 4 status](phase4_status.md).

| Input | Official source | Installed path |
|---|---|---|
| NF-UNSW-NB15-v2 | [University of Queensland download](https://rdm.uq.edu.au/files/8c6e2a00-ef9c-11ed-827d-e762de186848) | `data/raw/NF-UNSW-NB15-v2.csv` |
| NF-CSE-CIC-IDS2018-v2 | [University of Queensland download](https://rdm.uq.edu.au/files/ce5161d0-ef9c-11ed-827d-e762de186848) | `data/raw/NF-CSE-CIC-IDS2018-v2.csv` |
| Fashion-MNIST debug tier | [Zalando Research files and MD5 checksums](https://github.com/zalandoresearch/fashion-mnist#Get-the-Data) | Four `.gz` IDX files under `data/raw/fashion/` |

Use **v2** NetFlow files. The v1 and v3 releases have different feature sets.
The importer accepts each NF CSV directly or a ZIP containing one CSV with the
expected filename. Download the four Fashion-MNIST files named
`train-images-idx3-ubyte.gz`, `train-labels-idx1-ubyte.gz`,
`t10k-images-idx3-ubyte.gz`, and `t10k-labels-idx1-ubyte.gz` into one directory.

On this Windows checkout, run from the repository root after obtaining the
files. Substitute the actual local download paths:

```powershell
python -m hyperweave.data.prepare --unsw C:\path\to\NF-UNSW-NB15-v2.zip --cse C:\path\to\NF-CSE-CIC-IDS2018-v2.zip --fashion-dir C:\path\to\fashion
python -m hyperweave.data.prepare
```

The importer refuses an existing NF destination, checks the required 43-column
header, checks the previously audited UNSW SHA-1, and verifies Fashion-MNIST
against the publisher's MD5 values. It writes `data/raw/import_manifest.json`
with source paths, file sizes, and hashes. The CSE SHA-256 is recorded rather
than compared with an unavailable published checksum. Import is **not** a full
content audit or a training run.

After import, stream both full CSVs through the audit. These commands write
reports and do not train or use sealed evaluation data:

```powershell
python -m hyperweave.data.audit_nf --csv data/raw/NF-UNSW-NB15-v2.csv --dataset nf_unsw_nb15_v2 --output runs/unsw_audit_01
python -m hyperweave.data.audit_nf --csv data/raw/NF-CSE-CIC-IDS2018-v2.csv --dataset nf_cse_cic_ids2018_v2 --output runs/cse_audit_01
```

Check each `audit.json` for 43 features, both binary classes, zero nonfinite
values and zero label/category conflicts. The earlier observed row counts were
2,390,275 UNSW and 18,893,708 CSE; treat a mismatch as a data version issue
to investigate. The original CSVs lack verified campaign and time fields, so
use the approved [endpoint-group alternate protocol](group_split_protocol.md).

## Artifacts generated by the later study

| Command | Required outputs |
|---|---|
| `python -m hyperweave.data.group_split --unsw data/raw/NF-UNSW-NB15-v2.csv --cse data/raw/NF-CSE-CIC-IDS2018-v2.csv --output runs/group_split_01` | `manifest.json`, public `a_train.npz`, `a_val.npz`, `b.npz`, private `sealed.npz` |
| `python -m hyperweave.baselines.phase4 --split runs/group_split_01 --output runs/phase4_group_01` | `registry.sqlite`, `normalizer.npz`, `noise_envelope.npz`, model checkpoints and int8 exports in `artifacts/`, `report.json` |
| `python -m hyperweave.demo.phase5 --study runs/phase4_group_01 --split runs/group_split_01` | Local offline dashboard; on-demand generated artifacts and `demo_actions.sqlite` |

The split and study commands are the start of research model training and
optimization. Keep each output directory and its `manifest.json`, SQLite
registries, checkpoints and int8 exports together; the demo verifies their
dataset lineage. Use fresh output directory names on reruns.

The original chronological claim still needs verified campaign/time metadata.
C1-C4 verdicts still need the original preregistered proposal thresholds; do
not fill them after results. A real-LLM Phase 4 cycle needs a configured model
client, and comparable research latency needs one physically pinned CPU core.
The scripted cycle and Windows debug timings do not satisfy those gates.
